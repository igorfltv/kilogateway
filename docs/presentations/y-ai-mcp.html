02 / Доступ и секреты

Корпоративные ключи остаются на сервере

Коннектор подставляет credential только в разрешённый запрос к нужной системе

ПодключениеКого видит корпоративная системаКто определяет доступ
ПерсональноеOAuth или API key сотрудникаКонкретного пользователяЕго аккаунт и policy gateway
СервисноеКлюч учётной записи интеграцииСервисную учёткуСервисная роль и ограничения gateway по пользователю и ресурсу

Серверная проверка

Права проверяются на каждом вызове. Аудит фиксирует инициатора, инструмент и результат без секретов.

Хранение credentials

Dev: текущий AES-GCM. Production: Vault либо PostgreSQL с envelope encryption через KMS.

Изоляция по владельцу и системе.

У корпоративного API отдельный credential. Входной токен MCP-клиента не передаётся дальше. Ключи отсутствуют в клиентских конфигах, промптах и ответах инструментов. MCP Authorization

03 / Первая версия

Один коннектор и сквозная проверка доступа

Первую интеграцию выбираем по реальному корпоративному сценарию

Объём MVP

  1. Remote HTTP MCP proxy
  2. Каталог и права на инструменты
  3. Персональные подключения
  4. MCP по запросу в обоих CLI

Критерии готовности

  • Запрет проверяется на tools/call
  • Чужие credentials недоступны
  • Ключ не покидает сервер
  • Вызов и отзыв работают в CLI
